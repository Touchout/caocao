# 劇本執行（EEX 直譯器）

檔案格式見 `docs/formats.md`「EEX 腳本」。這份記錄**執行語意**。位址是 VA（image base 0x400000）。

## 記憶體與變數

6.6 的劇本會用「指標變數」直接讀寫引擎記憶體（例如 S_002 用 p 掃 MOD 放在 0x511000 的「裝備專屬」表，
把 119 呂布改成 1024 無）。所以引擎保留一份跟原版位址相同的記憶體映像（`EngineMemory`：exe 各區段載入
0x400000 起），變數、旗標都放在裡面。

| 位址 | 內容 |
|---|---|
| 0x502000 + 4n | 整數變數 n（0 ≤ n < 0x1000）。MOD 設定都是整數變數，見 `修改器與修改記錄/變量計算+意義.txt` |
| 0x506000 + 4n | 指標變數 n（0 ≤ n ≤ 480） |
| 0x492F90 | 劇本 VM 物件（全域）；+0x0C 串流位置 |
| 0x492FC8（VM+0x38） | 旗標，0x2000 bytes = 65536 個，每個 byte 由高位元往低位元排 |
| 0x505FB0（變數 4076） | 讀寫寬度：1 byte、2 word、其他 dword |
| 0x501B00 | 0x0A 初始化局部变量 會清的 320 個 dword（同時清旗標 0–255） |

## 讀參數（0x4183F7）

處理函式都用 `read_param(型別)` 讀參數：讀 u16 型別，跟要的不同時回傳 0x80000000（i32、字串）或 0x8000（其他），處理函式看到就中止。
值的特殊規則（引擎 `ScriptVM.decode`）：

- 型別 04（i32）是負數、而且目前的 opcode < 0x6E：改讀**整數變數 −值**。（0x77、0x79 等 ≥ 0x6E 的指令照原值。）
- 武將型別（02、38、39）的值在 0xEFFF..0xFFFE：改讀**整數變數 0xFFFE − 值**（0xFFFF 是「無」）。

## 變數指令（已用原版驗證）

`tools/re/gen_vectors.py` 用 Unicorn 執行原版處理函式，隨機產生 1200 筆「輸入 → 輸出」，
`engine/core` 的 `VarOpsTest` 逐筆比對，全部吻合。實作在 `engine/core/.../script/VarOps.kt`。

**0x77 变量运算**（0x416C87）：參數（類別 51, 編號 04, 運算 53, 運算元類別 52, 運算元 04）

- 目標：類別 2 = 整數變數；1 = 指標變數 p 本身；0 = *p（p 存的位址）。
- 運算元：0 常數、1 *p（dword）、2 p、3 &p（位址）、4 整數變數、5 &整數變數（位址）。
- 運算：0 +=、1 -=、2 =、3 *=、4 /=（商）、5 %=（**乘以百分比**：目標 × X / 100）、6 M=（餘數）。
- 寫入寬度：目標是 p，或運算元類別 ≥ 2 時一律 dword；否則依變數 4076（**包括整數變數**）。
- *p 且 p 編號 ≥ 200 時另外記錄（0x413604）：p+0x464 = 寫入後的值，0x506F84+n = 寬度，p+0x8C8 第一次的運算元。

**0x79 变量测试**（0x415093）：（運算元類別 52, 值 04, 比較 56, 運算元類別 52, 值 04）

- 取值同上，但 *p 依變數 4076 的寬度讀（0x415133）。
- 比較（無號）：0 ==、1 >=、2 <=、3 ≠、4 <、5 >。

**0x05 变量测试**：兩組（要成立／要不成立），各為 (0x35, N) + N 個原始 u16 旗標編號。

**0x0B 变量赋值**（旗標編號 04, 值 27）：旗標 = 值 ≠ 0。

**0x78 整型变量赋值**（變數 04, 模式 54, 武將 02, 屬性 55）：模式 0 = 變數 ← 武將屬性；模式 1 = 武將屬性 ← 變數
（0x4202D8；屬性 → 位置在 0x415418）。屬性清單見 `tools/eex_types.json` 的型別 55。位置分三種：

- 武將執行期資料（`docs/battle.md`）：0 R形象另外在 0x50F800 + 2n；其餘照偏移，寬度 byte／word。
- 27 戰場特殊形象：S 形象表 0x501000 + 2n。
- 28–30、32–41（戰場編號、座標、朝向、目前 HP/MP、狀態）：戰場單位表；武將不在戰場上時什麼都不做（變數不變）。
  31 戰場行動標識反而在武將資料 +0x35。

寫入的副作用：頭像（1）同時寫頭像表 0x50F000 + 2n（0x423E30）；等級（18）往上調時呼叫升級函式 0x4073F3
（依兵種成長重算能力值，**還沒移植**，引擎記在 `vm.gaps`）；改 S 形象會重畫。
引擎：`script/Attributes.kt`。`tools/re/gen_attr_vectors.py` 在模擬器連續呼叫原版 2000 次（隨機屬性、武將、模式、值，
隨機戰場單位），記錄每次寫到的所有記憶體；`AttrTest` 重播，除了 27 筆升級以外全部一致。

**0x76 无条件跳转**（偏移 04）：讀完參數後，串流位置 += 偏移。只出現在少數 R 劇本，都是往回跳（迴圈）。

**0x16 信息**（字串）：變數 4071 = 0 時彈出訊息；不是 0 時寫進「歷史情報」（玩家從選單打開看的攻略，
4071 的值是格式，0xFF 清空），不彈出。字串開頭的數字是排序序號。文字裡的 `[C0D…]` 是顏色標記（C + 兩位十六進位顏色）。
處理函式 0x413A35，歷史情報緩衝區在 0x509000。

**0x14 对话**：文字開頭 `&名字` 或 `&編號` 指定說話者，一條指令裡可以有多段（`\n&` 開始下一段）。
戰場模式（0x40B922：遊戲狀態 == 3）且說話者確定時用戰場對話 0x45965D(文字, 說話者)，否則用一般對話框 0x42D5B0。

**0x38 武将能力设定**（武將, 項目, 運算 0 = 1 + 2 −, 值）：處理函式 0x412007，引擎 `data/Stats.kt`（規則見 `docs/battle.md`「能力值」）。
`tools/re/gen_stats_vectors.py` + `StatsTest`：3000 筆（0x38、0x78 寫能力、基礎值公式、項目 7/8 目前 HP/MP）跟原版一致。
項目 7/8 改戰場單位（0x45AA37，[0x505F30] 設定 2／增加 1，減少 = 設定成 0x4036B0 取的目前值 − 值），引擎 `battle/Units.kt`。
戰場上的 0x400–0x402（目前行動單位）還沒移植。

**0x0A 初始化局部变量**：旗標 0–255 = 0，0x501B00 起 320 個 dword = 0。

## 區塊與控制流程

分派函式 0x4109E6：讀 u16 opcode；> 0x7B 錯誤；0 → 回傳 3、1 → 回傳 4（並記下位置），交給上層；
其他查跳轉表（0x410A38，索引 = opcode − 2）。條件指令回傳 0/1，else（0x03）回傳 6。

引擎（`ScriptVM`）照原版的方式**直接在位元組串流上執行**，用區塊堆疊記每層的結束位置：

- section = 名稱（0x02 内部信息）+ 條件指令* + 0 + 長度 + 本體（延伸到 section 結尾）。條件都成立才執行本體。
- 區塊內遇到 opcode 0：在區塊結尾 → 區塊結束；否則後面是長度 + 子區塊，前面累積的條件都成立才進去，不成立就跳過。
- opcode 1 子事件 = 一個「頭」指令 + 長度 + 子區塊：
  頭是條件指令 → 依結果；頭是 0x03 else → 同一層上一個子事件**沒有**執行時才執行；其他（名稱）→ 一定執行。
- 0x0C 结束Section、0x0D 结束Scene：結束目前的 section／scene。
- 0x76 跳轉後，把不再包含新位置的區塊從堆疊彈出。

## 劇本的組成（戰場劇本 S_*）

- scene 0：開戰處理（戰前處置、敵軍等級調整、友軍／敵軍／我軍出場設定、裝備、背景＝地圖、戰場障礙、戰前對話）。
  開戰時執行一次。
- scene 1：戰場事件。每個 section 是一個事件，條件是回合（0x3F）、行動方（0x40）、武將進入地點／區域（0x25/0x26）、
  相鄰（0x2E）、狀態（0x36）、勝敗（0x42/0x43）等，並用「旗標 #N 未設定」確保只觸發一次。觸發時機見下面「戰場的回合流程」。
- scene 2：戰鬥結束後。

## 戰場的回合流程與事件檢查（進行中）

戰場主函式 0x44F058（戰場物件 0x4B3D08）：開戰初始化 0x44D2CA → 繼續執行 scene 0 剩下的部分（`while VM 執行中: 0x4180C1`）→
… → 回合迴圈 0x44EEE5。戰場物件：+1 勝敗（0 進行中、2 = 0x49 战斗结束、3 = 0x0E 战斗失败或回合用完、5 …）、+2 目前回合（從 0）、
+3 回合上限、+4 天氣、+0x10 行動方（0 我軍、1 友軍、2 敵軍）、+0x504、+0x520 我軍操作中。引擎：`battle/TurnFlow.kt`。

- **0x44EEE5 回合迴圈**（參數 = 讀檔接續，新戰鬥 0）：
  - +1 ≠ 0 → 結束：0x44EBE8((上限 − 回合) × 4)，回傳 +1。
  - 回合 ≥ 上限 → 訊息「因为战斗时间过长，撤退。」（0x42F699(2, 0x48E220)）；格 0–59 裡第一個武將 0（曹操）的單位撤退
    （0x441744(0, 0)，不看狀態）；都沒有而且格 0 在地圖上時格 0 撤退；+1 = 3，結束。
  - [0x4B4238] = 0；+1 = 0、新戰鬥、回合 ≠ 0 時天氣變化 0x449F91(0xFF)（亂數 0x47FB13）。
  - +1 = 0 時一回合 0x44ED7F；之後 +1 = 5 → 另一條結束路徑（0x4364BD、0x41BA73…）；否則 +2 加 1，回到開頭。
- **0x44ED7F 一回合**：0x410549；回合提示 0x44AC28(回合 + 1, 0, 參數, 0)；新戰鬥時：+0x10 = 0、**檢查事件**（回合 0 檢查兩次）；
  +1 ≠ 0 → 直接進 0x44E825（馬上結束）。否則 [0x505FB4] ≠ 2 時設 0、**0x44EE30(0)** 我方回合開始處理、0x423490(0x508998)、0x40EC9D；
  +0x520 = 1、0x449DE6(1)、**0x44E0D9 我軍操作**；+0x520 = 0、0x449DE6(0)；+1 = 0 時 **0x44E825 電腦方**。
- **0x44E825 電腦方**：+0x504 = 0；k = 0（友軍）、1（敵軍），+1 ≠ 0 就停：
  - k = 0：+0x10 = 1、檢查事件。k = 1：回合提示 0x44AC28(回合 + 1, 1, 0, 2)、+0x10 = 2、檢查事件、[0x505FB4] ≠ 2 時設 1、**0x44EE30(1)**。
  - 0x44DA7A(k == 0)；行動迴圈：兩輪（[0x500C47] = 0、1），每輪依優先度 p = 0..0xFA，掃格 0–59（友軍）或 60–249（敵軍）：
    在地圖上、0x425AC7（行動優先度）= p、0x425AD0 ≠ 7、0x425AF0(4)、(2) 都是 0 → 設成目前行動的單位（0x406240）、
    **移動執行 0x43AD3B**（AI），行動後 0x425AF0(2) 時 0x45B609；0x41B508／0x412D52 成立時同一優先度再掃一次；
    +1 = 0 而且 0x425AF0(2) 時 0x43FCC9、**檢查事件**。+0x504 ≠ 0 時重算 0x44DA7A、優先度從頭。**還沒移植**。
- **0x44EE30(我方 0／敵方 1) 回合開始處理**：格 0–59 或 60–249 每個單位 0x4263B0（狀態恢復、亂數）、0x43C940（能力狀態變化）；
  另一方的 0x508A00 旗標清 0（0x420952：我方時清格 60–249，敵方時清 0–59）；0x44DFC7；每個單位 0x43CDDD（地形／道具回復）。
  單位處理**還沒移植**（引擎記在 gaps）。
- **單位行動後**：0x439413 → 0x4065D9：檢查事件、0x42BC14。引擎：玩家單位移動完呼叫 `BattleSession.afterAction()`。
- **0x44C601 檢查事件**：n = VM+0x24（scene 1 的 section 數，0x410999），最多 n 次：0x4180C1、0x47EAC4，VM+8 ≠ 0 才繼續。
  模擬器實測（S_000 第 1 回合）：沒有旗標防重複的事件會被連續選中好幾次，引擎照做（選到就執行完再選，選不到就停，最多 n 次）。
  6.6 的 scene 1 第 0 段（「裝備專屬整合版」）每次都成立、而且跑 255 次的迴圈，所以每次檢查事件要執行很多指令。
  0x4180C1 → VM+0x28 ≠ 0 時 0x4100A1：逐 section 執行條件指令（直到 opcode 0），全部成立才執行本體（0x40FBEF）；不成立的 section 不會被標記，下次再檢查。
  所以每個 section 自己用「旗標 #N」防止重複觸發。
- **0x4100A1 選事件（已用原版驗證）**：VM+0x10 ≠ 0xFFFF（有事件執行到一半）時呼叫 vtable[+0xC] 繼續，否則
  0x42AD2D／0x410970 檢查後，逐 section（數目放 VM+0x24）：定位到 section 開頭、讀 0x0A 頭（VM+0x34 ≠ 0 時多讀一個 word），
  反覆呼叫 vtable[+8] 執行條件區的指令：回傳 1／0 = 條件指令的結果（AND 起來），2 = 一般指令（照常執行），3 = 遇到 opcode 0。
  全部成立就記下這個 section 和位置（**最後一個成立的贏**）。最後有記下的就把 VM 指到該 section 的 opcode 0 之後（0x40FBEF），回傳 1。
  VM 的虛擬函式表在 0x486610（[0] 0x40FFD0、[4] 0x40FE3D、[8] 0x4109E6、[0xC] 0x480612、[0x10] 0x418BBC）。
  引擎：`ScriptVM.selectEvent`／`startEvent`。驗證：`tools/re/gen_event_vectors.py` 在 32 個 scene 0 跟原版完全一致的關卡，每關 40 組隨機回合、行動方、scene 1 條件用到的旗標，呼叫原版 0x4100A1 比對選中的位置（`EventSelectTest`），全部一致。
- 呼叫 0x44C601 的地方：回合開始（0x44ED7F）、0x44E0D9、0x44E825（三處）、單位行動後 0x439413 → 0x4065D9（0x43DB23 之後）、
  AI 行動 0x449C0D → 0x4065D9、0x45B609、0x46D05A。
- **0x37 钱、章节编号、忠奸测试**（0x4118BD，已用原版驗證）：(項目, 值, 比較)。項目 0 金錢 dword [0x4B077C]、1 章節 =
  word [0x4B0776] / 2（最多 0x7F）、2 byte [0x4B0782]；比較 0 ≥、1 <、其他 =（無號）。
- **0x49 战斗结束**（0x417AD7）／**0x0E 战斗失败**（0x415890）：遊戲狀態 3 時戰場物件 +1 = 2／3（0x4144AB → 0x40BE38）。

## 軌跡比對（方法 2）

`docs/methodology.md` 方法 2 的工具：

1. 原版：`python3 tools/re/trace_original.py <Ekd5.exe> <S_nnn.eex> <scene> out/trace_<名>_orig.jsonl [出陣]`
   - 出陣（出戰名單）是玩家輸入，逗號分隔的武將編號，預設 `0`；開始前寫進名單（沒有 0x4A 的關卡沿用上一場），出陣選擇畫面 0x45E6B3 也回傳它。
   - 除了變數、旗標，也逐 byte 比對記憶體區域（`MEM_REGIONS`：配置表、0x46/0x47 計數、出戰名單、武將資料、單位表、修正紀錄、頭像表）。
   - 模擬器先做原版啟動時的初始化：VM 的虛擬函式表與結果欄位（`init_vm`）、單位表空格（`init_statics`）、暫存緩衝區物件 0x48B100、執行原版 Data 載入函式 0x41B639
     （攔截讀檔 0x41B533 直接給 Data.e5 的內容）。
   - 逐條呼叫原版處理函式（真實 VM 物件 0x492F90，記憶體跨指令保留）；區塊流程由 Python 驅動（規則同 ScriptVM）。
   - 攔截畫面函式，記錄事件、不真的執行：0x42D5B0 對話框／訊息、0x45965D 戰場對話、0x42F699 訊息視窗（0x69 旁白）、

   - 0x27 讓遊戲狀態變成 3（戰場）之後執行原版開戰初始化 0x44D2CA，紀錄標 `battle_init`；讀地圖檔 0x41FC89 直接給 Hexzmap.e5 的內容，
     圖片載入、解碼、畫地圖格、地圖 JPG 執行緒等畫面函式不執行（`SCREEN_STUBS`）。

     環境變數 `EMU_API_LOG=1` 會印出呼叫到的 Windows API。
   - Windows API 沒有實作：呼叫時照 stdcall 彈掉參數（個數表 `tools/re/winapi_args.py`）並回傳 0；GetTickCount 每次前進 1 秒
     （0x09 延时 之類的等待迴圈才會結束）。
   - 每條記錄：pos、op、條件結果、彈出文字、歷史情報、整數／指標變數與旗標的變化、`ok`（處理函式有沒有跑完）。

3. 比對：`python3 tools/re/compare_trace.py <原版> <引擎>`，路徑分岔就停，其餘逐條列出不同。選擇題兩邊都答 1。

現況（2026-10-23）：原版軌跡含開戰初始化（0x27 之後執行 0x44D2CA）。
- **S_000 scene 0 共 160 條完全一致**（含開戰初始化與之後所有單位操作，記憶體逐 byte）。
- **S_002 scene 0 共 358 條也完全一致**。0x32 武将移动 的移動執行（0x43AD3B）還沒移植，引擎暫代（直接放到目的地），
  這關的劇本移動剛好結果相同。原版的 0x32 很耗指令（每格都查特效），模擬器每條指令的預算是 2 億。

# 驗證方法：怎麼確認跟原版一樣

> 每個 session 實作任何「原版行為」之前都要讀這份。使用者 2026-10-23 確認的做法。

## 原則

**不推測原版行為，以原版主程式（`Ekd5.exe`）的實際行為當標準答案。**

過去的 bug 都是推測錯：

- 人物圖編號公式是用圖片猜的 → 夏侯惇顯示成曹操（v0.4.1 修正，改照 exe 0x4068A1）。
- 0x16 信息被當成一律彈出 → 開戰跳出一大串攻略（v0.4.1 修正，原版依變數 4071 決定是否寫進歷史情報）。

所以實作順序固定是：

1. 在 exe 找到負責這個行為的函式（`tools/re/` 的 xref、callgraph、disasm、decomp）。
2. 讀懂它，把規則寫進文件（`docs/battle.md`、`docs/script.md`、`docs/formats.md`），附上函式位址。
3. 在引擎實作。
4. **用下面的比對方法確認跟原版一致**，比對測試跟實作一起 commit。
5. 只有在 exe 裡真的找不到時才推測，而且要在程式碼和文件裡標明「推測」（欄位名前加 `?` 或 `guess`），列進 `docs/progress.md` 的待確認清單。

## 比對方法與時機

| | 開發中（邊做邊比，每個 session 都要做） | 最後（全部功能完成後的整體驗收） |
|---|---|---|
| 引擎公式（人物圖、移動、命中、傷害…） | 方法 1：函式比對 | 納入完整回歸測試套件 |
| 劇本表現（訊息、對話、配置、事件…） | 方法 2：劇本執行軌跡比對 | 249 個劇本全部分支跑過、出報表 |
| 整個遊戲實際玩起來 | 不做 | 方法 3／4 |

### 方法 1：函式比對（公式、計算）

用 Unicorn 模擬器直接執行原版 exe 裡的函式，餵大量隨機輸入，記錄輸出，存成測試資料；
引擎的 Kotlin 實作讀同一份資料逐筆比對，必須完全一致。

- 範例：`tools/re/gen_vectors.py` → `engine/core/src/test/resources/ccz/vm_vectors.json` → `VarOpsTest`
  （0x77/0x79/0x05/0x0B，1200 筆全部吻合）。
- 模擬器基礎：`tools/re/eexemu.py`（載入 exe 區段、Windows API 回傳 0、除以零當 0、沒映射的記憶體補零頁）。
- 注意：模擬器裡的物件位址跟真實不同（例如 VM 物件在模擬器是 0x10000000），產生資料時要換算回真實位址。
- 測試資料只含數字，可以進 repo；需要遊戲檔的測試用 `-Pgame=` 才會跑。

### 方法 2：劇本執行軌跡比對（劇本表現）

把原版的劇本執行器（分派函式 0x4109E6 + 各 opcode 處理函式）放進模擬器，跑真正的劇本：

- 原版呼叫「彈出訊息」「顯示對話」「放置武將」「寫歷史情報」這類內部函式時，攔下來記錄「呼叫了誰、參數是什麼」；
  寫入的關鍵記憶體（變數、旗標、單位表）也記錄。這串紀錄就是原版的**執行軌跡**。
- 引擎的 `ScriptVM` + `BattleSession` 跑同一份劇本，輸出同樣格式的軌跡。
- 兩邊逐筆比對；不一致的第一筆就是要修的地方。
- 需要玩家輸入或戰鬥結果的地方（選擇題答案、HP…），兩邊給同樣的輸入。

工具：`tools/re/trace_original.py`（原版軌跡）、引擎端的軌跡輸出、比對腳本。實作細節與「哪些內部函式對應哪種事件」
記在 `docs/script.md`「軌跡比對」。

### 方法 3：用 Wine 跑完整原版（最後做）

在 VM 的虛擬顯示器（Xvfb）上用 Wine 執行 `Ekd5.exe`，程式自動操作，在關鍵時間點讀原版記憶體（單位位置、HP、旗標、變數）
並截圖，跟引擎在同一時間點的狀態比對。比對**狀態**優先，截圖只當輔助。可行性還沒驗證（2026-10-23 時 VM 有 Xvfb、沒有 Wine）。

### 方法 4：使用者提供對照（最後做，或 1～3 做不到時）

使用者在電腦上玩原版，在指定時間點存檔或截圖；引擎讀存檔比對狀態。

## 目前的比對工具一覽

| 比對對象 | 產生標準答案（模擬器跑原版） | 引擎端測試／工具 |
|---|---|---|
| 變數指令 0x77/0x79/0x05/0x0B | `tools/re/gen_vectors.py`（只含數字，進 repo） | `VarOpsTest` |
| 開新遊戲後整個記憶體 | `tools/re/dump_memory.py` → `out/expected_memory.bin` | `NewGameTest` |
| 0x78 武將屬性讀寫 | `tools/re/gen_attr_vectors.py` → `out/attr_vectors.json` | `AttrTest` |
| 能力值、0x38、基礎值公式 | `tools/re/gen_stats_vectors.py` → `out/stats_vectors.json` | `StatsTest` |
| 劇本執行軌跡（方法 2） | `tools/re/trace_original.py` | `:desktop:trace` + `tools/re/compare_trace.py` |

- `out/` 的標準答案含遊戲資料衍生的數值，不進 git，由 `tools/setup_vm.sh` 產生。**檔案不存在時對應測試會印「略過」並通過**，
  新 session 要先確認 `out/` 裡有這三個檔。
- 改了模擬器（`tools/re/eexemu.py`、`trace_original.py`）之後要重新產生標準答案再跑測試。
- 模擬器裡沒有的東西（畫面、Windows API、檔案）用攔截處理，清單在 `docs/script.md`「軌跡比對」；
  遇到指令「在模擬器裡跑不完」，先找它卡在哪個函式（看最後執行的位址），判斷是畫面就攔截、是邏輯就補初始狀態。
- 玩家輸入（選擇題、出陣）兩邊給一樣的：選擇題一律第一個，出陣預設只派曹操。

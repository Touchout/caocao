# 戰鬥系統（逆向進度）

分析對象：`Ekd5.exe`（新改曹操傳 6.6 引擎，社群稱「Star 的新引擎」，在光榮原版上大量改寫）。
工具：`tools/re/`（xref、disasm、callgraph、decomp）。反編譯結果在 VM 的 `out/decomp/`，不進 git。
位址都是 VA（image base 0x400000）。

## 共用函式

| 位址 | 意義 | 狀態 |
|---|---|---|
| 0x40D2AB | `get_stats(攻方, i, 守方, j)` → (攻方第 i 項, 守方第 j 項)。項目：0 攻擊、1 防禦、2 精神、3 爆發、4 士氣 | 已確認 |
| 0x4101D9 | `effect(單位, 特效編號, …)` → 該單位擁有此特效時回傳特效值（多半是百分比），否則 0。特效名稱見 `out/exe_tables.json` 的 `effects` | 已確認語意，內部尚未讀 |
| 0x425AD9 | `pct(p, x) = p * x / 100` | 已確認 |

| 0x47FA89 | `add_cap(a, b, cap) = min(a + b, cap)`（有號比較） | 已確認 |

## 命中判定 0x43B4B6

```
rate = 物理 ? hit_rate_physical() : hit_rate_strategy()   // 0x43B623 / 0x43B730
if rate >= 100: 命中
if 變數4018 > 1:                       // MOD 的命中模式
    if rate >= 變數4018: 命中
    if rate <  變數4017: 未命中
重擲最多 2 次：
    if roll(rate): 命中
    if 變數4018 == 1 or rate < 85: 未命中
    rate -= 10
回傳值 = 結果 * 2
```

### 物理命中率 0x43B623

```
if 戰場狀態 == 2: return 100           // g_500e9a
if 守方特定狀態（0x47EF3D / 0x423FE8(2)）: return 100 或 0
(a, d) = get_stats(攻方, 爆發, 守方, 爆發)
rate = base_hit(a, d)                     // 0x43B53A
if effect(攻方, 30 攻擊絕對命中): return 100
if v = effect(攻方, 31 輔助攻擊命中): rate = rate * (100 + v) / 100   // 推測
if v = effect(守方, 32 輔助攻擊防禦): rate = sat_sub(rate, v)
return final_adjust(攻方, 守方, rate)      // 0x408EEE，尚未讀
```

### 基礎命中率 0x43B53A（跟原版曹操傳相同）

```
a = 攻方爆發, d = 守方爆發
if a >= 2d:   100
elif a >= d:  90 + (a - d) * 10 / d
elif a >= d/2: 60 + (a - d/2) * 30 / (d/2)
else:          30 + sat_sub(a, d/3) * 30 / (d/3)
```

## 物理傷害 0x43BC5A

參數：(攻方, ?, 守方, 是否反擊, 是否…)

```
if 守方不存在: 0
if 特殊情況 0x43637B: 固定值
if effect(攻方, 22 破甲攻擊) …                // 另一條路徑
(atk, def) = get_stats(攻方, 攻擊, 守方, 防禦)
if not 反擊 and not hit(): 0
dmg = level?(攻方) + 25                       // 0x412674
if atk >= def: dmg += (atk - def) / 5
else:          dmg = max(sat_sub(dmg, (def - atk) / 5), 1)
地形修正：0x413260 / 0x43F74F，差值為負時 dmg += pct(-diff * 5, dmg)
兵種相剋：p = 0x426737(…)；p != 100 時 dmg = max(pct(p, dmg), 1)
特效：34 減輕遠距損傷（守方）、25 衝鋒攻擊（攻方，乘以 g_500c48）、35 減輕物理損傷（守方）
if 反擊 and not effect(攻方, 72 強化反擊): dmg = max(dmg * 3 / 4, 1)   // 反擊傷害 75%
else: dmg += 0x478F08(攻方, dmg)               // 尚未讀
dmg = 0x412C78(攻方, 守方, dmg, …)             // 尚未讀
if not 反擊: dmg = 0x42423D(…)                 // 尚未讀
dmg = min(dmg, 守方目前 HP)
```

> 原版曹操傳的傷害是 (攻 − 防) / 2 + 等級 + 25；這個 MOD 改成 / 5，並加了大量特效。

## 我軍出戰名單、出場配置、敵軍等級（進行中）

### 出戰名單 0x48B350

u16 武將編號 × 最多 20，0xFFFF 結尾（映像初值全 0xFFFF）。寫入者：

- 0x418597 出陣選擇（0x4A 我军出场强制设定 的處理函式 0x415BD0 呼叫）：強制出場的 + 玩家選的，選完寫進名單。**這是玩家輸入**。
- 0x426551：從我軍單位格 0–19 抄回名單（呼叫者 0x425627，待查是什麼時候）。

沒有 0x4A 的關卡（例如 S_002）沿用**上一場**的名單，所以敵軍等級跟上一場的出陣有關。單獨比對某一關時，名單要當成輸入給兩邊。

### 出場配置（0x46 友軍、0x47 敵軍）→ 劇本 VM 物件裡的配置表

0x46（0x419B61）、0x47（0x407FBC）都呼叫 0x41240B(vm, 敵軍?, k = 10, 結束格, 起始格)：

- 友軍：每條指令固定 20 筆，格 20–39 + 20 × [0x500AD4]；敵軍：每條 80 筆，格 60–139 + 80 × [0x500AD5]。指令結束時計數 +1。
- 每筆參數（0x407EC6，型別表 0x407F7C）：`02 武將, 26 隱藏, 04 x, 04 y, 2B 方向, 3E 等級, 45 ?, 07 AI, 02 目標武將, 04 目標x, 04 目標y`，
  敵軍在武將後面多一個 `26`（第 12 個值）。武將 0xFFFF 的略過。0xFFFF 預設：隱藏 0、第 12 個 0、AI 1、等級 0、45 → 2。
- 配置表：0x492F90 + 0x2044 + 16·格（0x418DD0）：
  +0 u16 武將、+2 型別 45 的值、+3 **等級**、+4 x、+5 y、+6..7 = 0xFEFE、
  +8 旗標 = 方向位元（0x449B29，表 0x449B4D：0→0x20、1→0x08、2→0x40、3→0x10，其他 0x40）| 隱藏 ? 4 | 敵軍：1 |（第 12 個值 ≠ 0 ? 2）；友軍：2、
  +9..11 OR 上 Data.e5 原始武將資料 +0x1D..0x1F（武器、防具、輔助；只有前兩個的 0xFF 先變 0）、+0xC AI、
  AI 3–6 時 +0xE..0xF：AI 4、6 = (目標x, 目標y)，其他 = 目標武將。
- 實際的戰場單位之後才從配置表建立（待查）。

其他會動配置表的指令（引擎 `battle/Deployment.kt`，S_000、S_002 scene 0 軌跡逐 byte 一致）：

- **0x44 战斗初始化**（0x4121E2）：兩個計數歸零；武將 0x3FF +0x19 = 0；0x508A00 起 256 個 word 與旗標 0–255 清除；
  0x500BA0 起 0x50 bytes = 0xFF、0x500B78 起 0x28 bytes = 0、0x49CF68 起 128 個物件（0x40 bytes）的 +0x10/+0x28/+0x2E 清 0、
  [0x49CEE4] = 0xFFFF；配置表格 0–19 = 出戰名單（到 0xFFFF 為止），其餘 0xFFFF，每格 +8 = 0；
  0x4930C8 起 1000 bytes = [0x505EC4]、0x4934B0 起 0x640 bytes = 0；重設 0x4A 的兩份名單（0x41C96D）。
- **0x4A 我军出场强制设定**（0x415BD0）：讀一個 i32（沒用到）；5 個型別 38 加進強制名單 0x4B09DC（位置 [0x4B0A2C]），
  5 個型別 39 加進排除名單 0x4B0A04（位置 [0x4B0A30]），位置到 20 歸零；上限 [0x4B09DB] = 1；出陣 0x418597(0)：
  排除名單 20 格都 ≠ 0 時先放曹操；強制名單裡 ≠ 0、≠ 0xFFFF 且是我軍（標識 ≠ 0xFF，0x42AC58）的依序放入；
  上限 = max(上限, 人數 + 1)，等於時不開選擇畫面（0x4A 一定是這樣）；結果寫出戰名單；排除名單位置是 0 時重設兩份名單。
- **0x4B 我军出场设定**（0x415E33）：(格, x, y, 方向, 隱藏)。整數變數 985 低 16 位 ≠ 0xFFFF 時改寫 0x507680 + 3·格
  = (x, y, 隱藏, 0xFF)；否則格裡有武將且 +8 的低 2 位是 0 時寫 x、y，+8 dword = 方向位元 | 隱藏 ? 4。
- **0x48 敌方装备设定**（0x411CDB）：(武將, 道具 3B, 等級 49, 道具 3C, 等級 49, 道具 3D)，0xFFFF 當 0；
  從格 20 起找這個武將，+9..11 = 三個道具、+6..7 = 兩個等級。

### 0x52 兵种改变（0x414BD4）

寫武將 +0x2B；0x414B93 檢查三件裝備換兵種後還能不能用，不能就換掉（0x407961、0x407FD4，**還沒移植**）；
整數變數 4081 的低位 byte ≠ 0 時重算能力 0x4149CF：攻擊～士氣 = 等級成長 + 修正（0x41055D：0x66 號以前且我軍標識 == 0 才取紀錄）+ 五維；
HP、MP（只寫低 16 位）= 等級成長 + 修正 + 轉職加成（0x413FAC：2 × 階段 × 兵種值）+ Data.e5 原始 HP/MP。

### 敵軍等級

- 參考等級 0x4266C4 = 0x4184DD() + i8 [0x501BF4]（≤ 0 時 1）。
- 0x4184DD：出戰名單裡各武將等級由大到小排，取前 min(人數, 4) 個平均（人數 0 會除以零）。
- 0x4123C8(p = 等級參數, 參考, k)：p ≤ 100 → min(參考 + p, 100 + k)（無號 byte）；p > 100 → 參考 − (p − 100)，≤ 0 時 1。
  也就是 3E 型別的等級參數：≤ 100 是「參考 + p」，> 100 是「參考 − (p − 100)」。

## 開戰初始化（0x44D2CA，引擎 `battle/BattleInit.kt`）

### 時序

劇本執行到 **0x27 背景显示（模式 3 = 戰場）**：處理函式 0x413D13 寫地圖編號 0x510CFE（= 值 + 變數4051 × 100，之後變數4051 歸 0），
呼叫 0x428346 把遊戲狀態（byte 0x4AC63C）設成 3，並設 [0x4ABF9C] |= 2 讓劇本暫停。主迴圈 0x42C228 看到狀態 3 進戰場
0x44F058（戰場物件 0x4B3D08）：讀檔進來的戰場（[0x497738] ≠ 0）走 0x44D0AF，新戰場走 **0x44D2CA**；初始化完才繼續執行劇本
（0x44F058 的 `while VM+8: 0x4180C1`）。所以 scene 0 裡 0x27 之前的 0x46/0x47/0x4B 只是填配置表，0x27 之後的對話、
0x32 移動、0x4C 伏兵出現、0x31 武將消失 才是對戰場單位操作。

### 0x44D2CA 裡跟戰場狀態有關的步驟（依序）

1. 戰場物件欄位清 0、0x501AE1 起 31 bytes（第一個 0、其餘 0xFF）、[0x48BAE0] = [0x48BAE8] = 0xFFFF、
   0x4B3D21 起 0x4E2 bytes = 0xFF、**佔位表**（緩衝區 8 + 0xC80，0x640 bytes）= 0xFF。
2. 0x435A8D：250 格全部重設（0x47D0BC）。
3. 0x413EAA → 0x407D08 → **0x44C1C2 載入地圖**：Hexzmap.e5 第 [0x510CFE] 項，寬 = byte0 / 3、高 = byte1 / 3 寫 [0x4B422C]、[0x4B422D]，
   地形（寬 × 高 bytes）複製到緩衝區 8 + 0x640。
4. **0x43BB15 建立單位**：先把 Data.e5 第 0 項讀進暫存緩衝區，再依序看配置表格 0–249（武將 0xFFFF 略過），旗標 f = 配置 +8：
   - f & 3 == 0（我軍）：單位格 = 我軍計數（從 0）++，0x40C990(武將, f, x, y)。
   - 友軍（f & 1 == 0、f & 2 ≠ 0）且武將是我軍（標識 ≠ 0xFF，0x42AC58）：格 = 友軍計數（從 20）++，0x40C990，接著設 AI（下面）。
   - 其他友軍：格 = 友軍計數++；敵軍（f & 1）：格 = 敵軍計數（從 60）++。都走 0x42AD35(f, 配置, 武將, &配置+4)，接著設 AI。
   - 設 AI 0x459D95(武將, 配置 +0xC AI, +0xE..0xF, +0xE, +0xF, 格)。
5. 每一格（0–249）：0x406690(0x80) 清 +0x0D bit 0x80、0x423FB9(0x1E) 清健康狀態；在地圖上的（+0x0C ≠ 0）載入單位圖（畫面）；
   格 < 60 且陣營是我軍（0x413172 == 0）的設 +0x0E = 7。
6. 0x44D227 等（未讀）。

### HP/MP 上限與裝備加成（引擎 `data/Equipment.kt`，`HpMpTest` 3000 筆與原版一致）

- **HP 上限 0x407263** = min(裝備加成(5) + 基礎, 0xFFFF)（有號比較），基礎 = +0x1B 的低 16 位；
  **MP 上限 0x40728F** = min(裝備加成(6) + +0x1F, 9999)。
- 基礎值的 MOD 選項 0x405B86：整數變數 4046 的低位 byte ≠ 0 時 基礎 + 基礎 × (+0x35 / 15) / 100。
- **裝備加成 0x407C29(項目)**：武器、防具（欄 0、1）：
  - 道具種類（+0x11）對應的能力項目（0x4067CE：種類 < 0x1A 查表 0x40684F[種類 / 2]，0x20–0x26 → 0–6、0x27 → 8、0x28 → 7、
    0x5C → 9、0xFE → 10）等於項目時（10 算攻擊與精神），加上道具數值 0x40B3D7 = +0x15 + 會成長時 +0x17 × (等級 − 1)。
    會成長 0x40C45A：種類 < 0x1A，或 +0x14 ≤ 1。
  - 會成長且種類是奇數（0x40B4E1）、特效 +0x14 對應的項目（0x40678E）等於項目時，再加特效值 0x4200F5（+0x16 依特效與等級調整，
    等級 ≥ 10 時可能換成 MOD 表 0x4CB5CA 的固定值）。
  - 輔助（欄 2）：種類對應的項目等於項目時加 +0x15。
  - 特效值與輔助的加成經過 0x452825：MOD 表 0x4CB6C0[項目] == 2 時是百分比（基礎 × 值 / 100）。
  - MOD 表 0x4CB5CA／0x4CB6BA／0x4CB6C0 在 exe 的 `.api` 區段，是靜態資料。

### 敵軍裝備 0x44299B(欄, 值, 等級)

配置 +9／+0xA／+0xB（開戰時 OR 上 Data.e5 原始武將資料的武器、防具、輔助）、等級 +6／+7（0x48 敌方装备设定 寫的，預設 0xFEFE）：

- 值 0xFF、≥ 150 不換；**0 = 自動配裝** 0x407FD4：階 = min(L / 20, 2)、等級 = L ≥ 60 ? 5 : (L % 20) / 4 + 1（L = 武將等級），
  種類 = 兵種表 +9 起第一個可以用的（武器 0–19、防具 20–25），道具 = 表 0x482427[種類 / 2] + 階，經驗 = 等級 ≥ 5 ? 0xFF : 0。
- 1 = 卸下（0x420649；我軍標識 0 且等級 dword == 1 時還會放回道具欄，未移植）。
- 其他 = **指定道具** 0x407DF1：道具 = 值 − 2（防具 + 70、輔助 + 109，對應 System.ini 的 DefID／AssID）；等級 0xFE 時道具 = 值、等級 0。
  道具類別（0x40B444：種類 < 0x14 → 0、< 0x1A → 1、其他 = +0x14）跟欄位不合就不裝。等級 0 = 依武將等級（會成長的奇數種類
  min(L / 6 + 1, 9)，其他同自動配裝），超過上限（奇數種類 10、其他 5）取上限；經驗 = 等級 < 上限 ? 0 : 0xFF，等級 9 再減 1。
  輔助只寫道具編號。

### 換兵種後的裝備檢查 0x414B93（0x52 兵种改变）

## 劇本對單位的操作（引擎 `battle/BattleField.kt`）

都只在戰場狀態有效（0x40B922：遊戲狀態 3），直接改單位表與佔位表。

**找單位**：0x41B882(武將參數)：≥ 0x404 = 格號 − 0x404（空格 = 沒有）；[0x505EFC] ≠ 0 且 < 0xFA 時也當格號；其他回傳 0，
呼叫端再用武將編號找：0x456079（第一個武將相符、狀態 ≠ 0 的）或 0x4029C2／0x43E4D6（第一個武將相符的，不看狀態）。
武將 0x400–0x402 代表目前行動的單位等（0x418CE0，還沒移植）。

**陣營篩選**：0x42E2ED 分類（格 < 20 → 0、< 60 → 1；其他依 +5：2 → 2、3 → 3、5 → [0x501AD8+格] ≠ 0 ? 4 : 2、6 → … ? 5 : 3），

範圍版：0x31／0x53（0x45A80F）、0x4E（0x459E79）把 x1、y1 限制在地圖內；0x4D（0x45ADE7）不限制。

**移除 0x441744(消失, 旗標)**（經 0x45A7A2，它前後設、清 +0x0D bit 0x80）：狀態要是 2；清佔位（0x40D84B）；

## 能力值

### 能力項目與成長（引擎 `data/Stats.kt`，3000 筆與原版一致）

能力項目編號（0x38 用）：0–4 攻擊、防禦、精神、爆發、士氣（武將資料 +0x11 起 word），5 HP（+0x1B dword），6 MP（+0x1F word），
7/8 目前 HP/MP（戰場單位），9 等級（+0x2C），10–14 武力～運氣（+0x21 起 byte），15 頭像（+0x04）。

- **基礎值（等級成長總和）0x408A60**：兵種 c、等級 L。c ≤ 59 時 c % 3 是轉職階段：第 2 階且 L ≥ 30 → 15 級算兵種 c−1；
  接著（第 1、2 階）L ≥ 15 → 15 級算再低一階；剩下的 L 算兵種 c。結果 = Σ 每級成長 × 級數。
- **每級成長 0x4250B6**：g = 兵種表（0x4A2A27 + 0x23·c）第 2 + 項目 byte + 成長修正。項目 0–4：(等第 + g) / 2（負數當 0）；其他：g。
- **等第 0x4072F2**：對應五維 ≥ 99 → 10、≥ 90 → 8、≥ 70 → 6、≥ 50 → 4、其他 2（再加成長修正）。
- **成長修正 0x436E3D**：MOD 表 0x507EC0（`FF 項目 {i8 值, u16 武將}* … FF FF`），找到就加上值（負數 +1）。6.6 的表是空的。
- 0x408B52 修正紀錄的「設定」公式：攻擊等 = 五維 + 基礎值 + 紀錄，所以紀錄 = 新值 − 五維 − 基礎值。
- 上限：0–4、MP 9999；HP 設定時 0xFFFF、增加時 9999；五維 100。增加用 `min(a + b, 上限)`（可以是負數）；減少用飽和減法。

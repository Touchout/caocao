# 進度與規劃

> 新 session 先讀這份和 `CLAUDE.md`，再跑 `tools/setup_vm.sh` 重建環境。
> 每完成一個步驟就更新這份文件並 commit + push：session 可能隨時換新，沒寫進來的進度等於沒做。

## 目前狀態（最後更新：2026-10-23）

- 重現對象：**新改曹操傳 6.6 修正版**（使用者決定，不是原版）。
- 成品：Android App（Kotlin，`engine/`），執行時讀玩家自己的遊戲檔，所有文字顯示繁體（台灣用字）。
- 最新 APK：**v0.4.2**（`out/caocao-0.4.2-debug.apk`）：戰場單位改由原版開戰初始化建立（位置、伏兵、HP/MP、敵軍等級裝備與原版一致），
  劇本的轉向／伏兵出現／消失／撤退照原版。待使用者實機確認。
- 驗證方法照 `docs/methodology.md`（使用者 2026-10-23 確認）：**不推測，用模擬器跑原版 exe 當標準答案**。
- v0.5 第 0 步（軌跡比對工具）**完成**：S_000、S_002 scene 0 跟原版逐條、逐 byte 一致。過程中引擎的狀態已改成
  「跟原版同位址、同格式的記憶體」（`EngineMemory`）：武將、道具、兵種、地形、策略、能力值、出場配置表、出戰名單都在裡面。
- **接手從下面「進行中」的「下一步」開始。**

驗證：照 `docs/methodology.md`。開發中每個公式用方法 1（函式比對）、每個劇本指令用方法 2（軌跡比對）對照原版；
完整回歸測試套件與整體驗收（方法 3 Wine／方法 4 存檔）放到全部功能完成之後（使用者 2026-10-23 同意）。

## 決策紀錄

- 戰場地圖編號由劇本 0x27 背景显示（模式 3）的型別 0x15 參數決定，不一定等於關卡編號。
- 座標順序 (x, y)。朝向 0 北、1 東、2 南、3 西。人物圖：0–239 兵種通用圖（兵種×3 + 陣營 0 我/1 友/2 敵），240 起武將專屬圖（240 + S形象 − 1），
  劇本 0x75 可以改形象。
- EEX 每個 opcode 的參數型別表是用 Unicorn 模擬 exe 量出來的（`tools/re/eexemu.py`），結果在 `tools/eex_signatures.json`，
  引擎用的是 `engine/core/src/main/resources/ccz/eex/signatures.txt`。
- 簡轉繁用 OpenCC s2twp 字典（Apache 2.0），放在 core resources。
- Maven Central 常回 429：Gradle 先走 Google 的 Maven Central 鏡像。VM 沒有 KVM，不能跑 Android 模擬器，
  用 `engine/desktop` 把畫面畫成 PNG 驗證。

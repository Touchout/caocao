# 劇本執行（EEX 直譯器）

檔案格式見 `docs/formats.md`「EEX 腳本」。這份記錄**執行語意**。位址是 VA（image base 0x400000）。

## 記憶體與變數

6.6 的劇本會用「指標變數」直接讀寫引擎記憶體（例如 S_002 用 p 掃 MOD 放在 0x511000 的「裝備專屬」表，
把 119 呂布改成 1024 無）。所以引擎保留一份跟原版位址相同的記憶體映像（`EngineMemory`：exe 各區段載入
0x400000 起），變數、旗標都放在裡面。

| 位址 | 內容 |
|---|---|
| 0x502000 + 4n | 整數變數 n（0 ≤ n < 0x1000）。MOD 設定都是整數變數，見 `修改器與修改記錄/變量計算+意義.txt` |
| 0x506000 + 4n | 指標變數 n（0 ≤ n ≤ 480） |
| 0x492F90 | 劇本 VM 物件（全域）；+0x0C 串流位置 |
| 0x492FC8（VM+0x38） | 旗標，0x2000 bytes = 65536 個，每個 byte 由高位元往低位元排 |
| 0x505FB0（變數 4076） | 讀寫寬度：1 byte、2 word、其他 dword |
| 0x501B00 | 0x0A 初始化局部变量 會清的 320 個 dword（同時清旗標 0–255） |

## 變數指令（已用原版驗證）

`tools/re/gen_vectors.py` 用 Unicorn 執行原版處理函式，隨機產生 1200 筆「輸入 → 輸出」，
`engine/core` 的 `VarOpsTest` 逐筆比對，全部吻合。實作在 `engine/core/.../script/VarOps.kt`。

**0x77 变量运算**（0x416C87）：參數（類別 51, 編號 04, 運算 53, 運算元類別 52, 運算元 04）

- 目標：類別 2 = 整數變數；1 = 指標變數 p 本身；0 = *p（p 存的位址）。
- 運算元：0 常數、1 *p（dword）、2 p、3 &p（位址）、4 整數變數、5 &整數變數（位址）。
- 運算：0 +=、1 -=、2 =、3 *=、4 /=（商）、5 %=（**乘以百分比**：目標 × X / 100）、6 M=（餘數）。
- 寫入寬度：目標是 p，或運算元類別 ≥ 2 時一律 dword；否則依變數 4076（**包括整數變數**）。
- *p 且 p 編號 ≥ 200 時另外記錄（0x413604）：p+0x464 = 寫入後的值，0x506F84+n = 寬度，p+0x8C8 第一次的運算元。

**0x79 变量测试**（0x415093）：（運算元類別 52, 值 04, 比較 56, 運算元類別 52, 值 04）

- 取值同上，但 *p 依變數 4076 的寬度讀（0x415133）。
- 比較（無號）：0 ==、1 >=、2 <=、3 ≠、4 <、5 >。

**0x05 变量测试**：兩組（要成立／要不成立），各為 (0x35, N) + N 個原始 u16 旗標編號。

**0x0B 变量赋值**（旗標編號 04, 值 27）：旗標 = 值 ≠ 0。

**0x78 整型变量赋值**（變數 04, 模式 54, 武將 02, 屬性 55）：模式 0 = 變數 ← 武將屬性；模式 1 = 武將屬性 ← 變數
（0x4202D8，依屬性查兩張函式指標表）。屬性清單見 `tools/eex_types.json` 的型別 55。

**0x76 无条件跳转**（偏移 04）：讀完參數後，串流位置 += 偏移。只出現在少數 R 劇本，都是往回跳（迴圈）。

**0x16 信息**（字串）：變數 4071 = 0 時彈出訊息；不是 0 時寫進「歷史情報」（玩家從選單打開看的攻略，
4071 的值是格式，0xFF 清空），不彈出。字串開頭的數字是排序序號。文字裡的 `[C0D…]` 是顏色標記（C + 兩位十六進位顏色）。
處理函式 0x413A35，歷史情報緩衝區在 0x509000。

**0x0A 初始化局部变量**：旗標 0–255 = 0，0x501B00 起 320 個 dword = 0。

## 區塊與控制流程

分派函式 0x4109E6：讀 u16 opcode；> 0x7B 錯誤；0 → 回傳 3、1 → 回傳 4（並記下位置），交給上層；
其他查跳轉表（0x410A38，索引 = opcode − 2）。條件指令回傳 0/1，else（0x03）回傳 6。

引擎（`ScriptVM`）照原版的方式**直接在位元組串流上執行**，用區塊堆疊記每層的結束位置：

- section = 名稱（0x02 内部信息）+ 條件指令* + 0 + 長度 + 本體（延伸到 section 結尾）。條件都成立才執行本體。
- 區塊內遇到 opcode 0：在區塊結尾 → 區塊結束；否則後面是長度 + 子區塊，前面累積的條件都成立才進去，不成立就跳過。
- opcode 1 子事件 = 一個「頭」指令 + 長度 + 子區塊：
  頭是條件指令 → 依結果；頭是 0x03 else → 同一層上一個子事件**沒有**執行時才執行；其他（名稱）→ 一定執行。
- 0x0C 结束Section、0x0D 结束Scene：結束目前的 section／scene。
- 0x76 跳轉後，把不再包含新位置的區塊從堆疊彈出。

## 劇本的組成（戰場劇本 S_*）

- scene 0：開戰處理（戰前處置、敵軍等級調整、友軍／敵軍／我軍出場設定、裝備、背景＝地圖、戰場障礙、戰前對話）。
  開戰時執行一次。
- scene 1：戰場事件。每個 section 是一個事件，條件是回合（0x3F）、行動方（0x40）、武將進入地點／區域（0x25/0x26）、
  相鄰（0x2E）、狀態（0x36）、勝敗（0x42/0x43）等，並用「旗標 #N 未設定」確保只觸發一次。觸發時機待查。
- scene 2：戰鬥結束後。

## 已知但還沒處理

- 敵軍等級：0x45 战场全局变量 的參數（3E 位置的 102 或 10，依旗標 #1700）決定，算法待查。
- 頭像：Data.e5 的頭像欄位就是 Face.e5 索引，但 6.6 會在開頭的 R 劇本用 0x78 改寫（例如夏侯惇戴眼罩是 8 號）。
  直接進戰場時看到的是預設頭像。
- 0x48 敌方装备设定 的防具／輔助編號不是從 0 起（System.ini：防具從 70、輔助從 109），反組譯顯示的名稱是錯的。
- 0x72 信息传送：MOD 的擴充函式呼叫（第一個整數是函式編號，見 CczString.ini 第 14 行），例如習得特技、裝備專屬。
